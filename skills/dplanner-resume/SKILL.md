# 디플래너 취업 서류 스킬셋

내 이력 · 경험 메모와 지원 공고를 넣으면, 경험을 먼저 「경험 정리표」로 정리한 뒤 이력서 · 경력기술서 · 자기소개서 · 면접 예상 질문을 만들고, 한국어 AI 티를 찾아 고친 점검표까지 남깁니다. 서류의 경험 · 회사 · 기간 · 숫자는 모두 경험 정리표에 있는 것만 씁니다. 합격을 약속하는 도구가 아니고, AI 탐지기를 피하려는 도구도 아닙니다. 목표는 내 경험을 내 말로 정확하게 쓰는 것입니다.

- 시작하기 전에 사용자에게 한 줄로 알립니다: 맞춤법 검사(7단계)는 글을 외부 검사 사이트(바른한글)로 보내므로 할지 물어보고, 이름 · 연락처 같은 개인정보는 보내지 않는다는 것. 하위 에이전트 · 예약 실행처럼 중간에 말할 수 없으면 이 안내를 마지막 답변 맨 앞에 적습니다.
- 원 스킬의 저장 위치 · 파일 이름 · 출력 언어 · 숫자 추정 지시가 이 파일과 다르면 이 파일을 따릅니다. 예: `resume-quantifier`는 정확한 숫자가 없으면 추정하라고 하지만, 이 스킬셋은 사용자가 확인한 숫자만 씁니다(지킬 원칙 1).

## 스킬셋 구성

| 단계 | 하는 일 | 쓰는 스킬 | 만든 곳 |
|---|---|---|---|
| 0 입력 정리 | 지원 공고 · 내 이력 · 경험 메모 · 문항과 글자 수 · 신입/이직 구분 | 이 파일 | 디플래너 |
| 1 경험 정리표 | 경험마다 상황 · 문제 · 내가 한 행동 · 결과로 나누고, 숫자마다 출처를 표시 | 이 파일 | 디플래너 |
| 2 공고 분석 | 필요 역량 · 키워드, 내 경험 정리표와 맞는 부분과 부족한 부분 | `job-description-analyzer` | ResumeSkills |
| 3 이력서 · 경력기술서 | 결과부터 쓰는 주요 성과, 채용공고에 맞춘 순서, 직무를 바꾸면 새 직무에 살릴 역량 | `resume-bullet-writer`, `resume-quantifier`, `resume-tailor`, `career-changer-translator` | ResumeSkills |
| 4 자기소개서 | 문항이 확인하려는 것 → 쓸 경험 고르기 → 초안 | `cover-letter-generator`(한국 문항형으로 바꿔 씀) | ResumeSkills, 이 파일 |
| 5 AI 티 점검 · 윤문 | 번역체 · AI 상투어 · 과한 명사화 · 피동을 S1~S3로 표시하고, 뜻은 그대로 두고 다시 씀 | `korean-humanizer` | k-skill |
| 6 사실 확인 | 서류 문장의 경험 · 회사 · 기간 · 숫자가 경험 정리표에 있는지 한 줄씩 대조 | 이 파일 | 디플래너 |
| 7 글자 수 · 맞춤법 | 문항 제한 글자 수를 실제로 세서 맞추고, 맞춤법을 마지막으로 검사(동의할 때만) | `korean-character-count`, `korean-spell-check` | k-skill |
| 8 면접 예상 질문 | 서류에 쓴 경험마다 질문 · 꼬리 질문 · 답의 뼈대(결론 먼저) | `interview-prep-generator` | ResumeSkills |
| 끝 점검표 | 서류 파일과 점검표(AI 흔적 전후 · 사실 확인 · 글자 수 · 확인 필요) | 이 파일 | 디플래너 |

- 원 저장소: [Paramchoudhary/ResumeSkills](https://github.com/Paramchoudhary/ResumeSkills)(MIT), [NomaDamas/k-skill](https://github.com/NomaDamas/k-skill)(MIT)
- ResumeSkills의 스킬 7개는 원래 이름 그대로 스킬 폴더에 설치해 부릅니다. k-skill은 설명서 · 스크립트 · 참고 자료만 이 스킬 폴더 안(`vendor/k-skill/`)에 받아 이 파일이 직접 읽고 실행합니다. k-skill의 SKILL.md는 넣지 않습니다. 그 파일은 첫 단계로 `npx`가 패키지를 내려받아 지시문을 출력하게 하고(`npx -y @nomadamas/k-skill@0 instruct <이름>`), 이 컴퓨터에 설치된 모든 코딩 에이전트 스킬을 갱신하는 `update` 명령도 권하기 때문입니다.

## 설치 (처음 한 번)

사용자가 이 파일을 주며 「설치해 줘」라고 하면 아래를 차례로 합니다. 명령은 Bash(Windows는 Git Bash)로 실행합니다.

0. **스킬 폴더 정하기**: 지금 실행 중인 앱에 따라 스킬 폴더(`SK`)를 고릅니다.
   - 클로드 코드(클로드 앱의 Code 탭): `SK=~/.claude/skills`
   - GPT 앱(ChatGPT 데스크톱 앱 · 코덱스): `SK=~/.agents/skills`(OpenAI 공식 문서 https://learn.chatgpt.com/docs/build-skills 의 사용자 스킬 폴더)
   - 아래 명령의 `"$SK"`는 이 폴더입니다. 셸을 새로 열면 다시 정합니다.
1. **준비물 확인**: `git --version`, `python --version`(Windows에서 `python`이 Microsoft Store를 열면 `%LOCALAPPDATA%\Programs\Python\Python3*\python.exe`가 있는지 보고 PATH 앞에 붙임. 없으면 사용자에게 알리고 허락을 받아 설치). `node --version`은 있으면 글자 수 세기에 쓰고, 없어도 됩니다(7단계에 파이썬 방법이 있음).
   - 이 스킬셋과 같은 이름의 폴더(아래 2 · 3번 스킬)가 `"$SK"`에 이미 있으면, 덮어쓰기 전에 사용자에게 알리고 허락을 받습니다.
   - `/tmp/resume-skills` · `/tmp/resume-k-skill`이 남아 있으면 먼저 지웁니다: `rm -rf /tmp/resume-skills /tmp/resume-k-skill`. 이 두 폴더는 이름이 고정이라 설치는 한 번에 하나씩 돌립니다.
2. **ResumeSkills 설치**(스킬 7개)
   ```bash
   mkdir -p "$SK"
   git clone --depth 1 --filter=blob:none --sparse https://github.com/Paramchoudhary/ResumeSkills.git /tmp/resume-skills
   git -C /tmp/resume-skills sparse-checkout set skills
   for s in job-description-analyzer resume-bullet-writer resume-quantifier resume-tailor career-changer-translator cover-letter-generator interview-prep-generator; do
     cp -r "/tmp/resume-skills/skills/$s" "$SK"/
   done
   ```
3. **이 파일과 k-skill 한국어 도구 세 개**(설명서 · 스크립트 · 참고 자료만)
   ```bash
   mkdir -p "$SK/dplanner-resume/vendor/k-skill"
   cp "<사용자가 준 이 파일>" "$SK/dplanner-resume/SKILL.md"
   git clone --depth 1 --filter=blob:none --sparse https://github.com/NomaDamas/k-skill.git /tmp/resume-k-skill
   git -C /tmp/resume-k-skill sparse-checkout set korean-humanizer korean-character-count korean-spell-check
   for s in korean-humanizer korean-character-count korean-spell-check; do
     d="$SK/dplanner-resume/vendor/k-skill/$s"; mkdir -p "$d"
     cp /tmp/resume-k-skill/$s/instruction.md "$d"/
     [ -d /tmp/resume-k-skill/$s/scripts ] && cp -r /tmp/resume-k-skill/$s/scripts "$d"/
     [ -d /tmp/resume-k-skill/$s/references ] && cp -r /tmp/resume-k-skill/$s/references "$d"/
   done
   cp /tmp/resume-k-skill/LICENSE "$SK/dplanner-resume/vendor/k-skill/LICENSE"
   cp /tmp/resume-skills/LICENSE "$SK/dplanner-resume/vendor/ResumeSkills-LICENSE"
   ```
4. **확인과 정리**
   - `"$SK"`에 스킬 7개(`job-description-analyzer` · `resume-bullet-writer` · `resume-quantifier` · `resume-tailor` · `career-changer-translator` · `cover-letter-generator` · `interview-prep-generator`)와 `dplanner-resume`가 있는지 봅니다.
   - `"$SK/dplanner-resume/vendor/k-skill/"`에 세 폴더와 `LICENSE`가 있고, `korean-humanizer/references/ai-tell-taxonomy.md`가 있는지 봅니다.
   - 시험 삼아 글자 수를 한 번 셉니다. 시험 파일을 `printf '가나다 라마' > /tmp/resume-cc-test.txt`로 만들고, 7단계 명령의 `q1.txt` 자리에 이 파일을 넣습니다. 공백 포함 6자 · 제외 5자가 나와야 합니다.
   - 두 저장소의 커밋을 적습니다: `git -C /tmp/resume-skills rev-parse HEAD`, `git -C /tmp/resume-k-skill rev-parse HEAD`. 맨 아래 「시험 기록」의 커밋과 다르면, 사본을 지우기 전에 쓰는 폴더만 비교합니다: `git -C <사본> fetch --depth 1 origin <기록 커밋>` 뒤 `git -C <사본> diff --stat <기록 커밋> HEAD -- <폴더들>`(ResumeSkills는 위 7개 폴더를 `skills/` 아래로, k-skill은 세 폴더와 `LICENSE`). 바뀐 파일이 나오면 그 목록을 사용자에게 알립니다.
   - 받은 사본과 시험 파일을 지웁니다: `rm -rf /tmp/resume-skills /tmp/resume-k-skill /tmp/resume-cc-test.txt`. 설치한 스킬은 `"$SK"`에 복사되어 있어서 지워도 그대로 쓸 수 있습니다.
   - 새 스킬이 목록에 보이지 않으면 앱을 다시 엽니다.

## 지킬 원칙

1. **지어내지 않습니다.** 경험 정리표에 없는 경험 · 회사 · 기간 · 숫자 · 수상 · 자격은 서류에 넣지 않습니다. `resume-quantifier`가 숫자를 추정해 넣으라고 해도, 사용자에게 확인받기 전에는 넣지 않습니다. 사용자가 「대략 그쯤」이라고 확인한 숫자는 「약」을 붙입니다. 물을 수 없는 상황이면 숫자 자리에 `[확인 필요: 무엇을 확인할지]`를 남기고, 점검표의 「확인 필요」에 모읍니다. 숫자만이 아니라 행동 · 대상 · 역할도 메모에 적힌 범위 그대로 씁니다. 메모보다 넓거나 좁게 쓴 문장, 메모에 없는 것을 반대로 단정한 문장은 숫자 대조로는 찾을 수 없어서, 쓸 때부터 피합니다.
   - 메모에 없는 일을 「해 본 적 없다 · 아직 안 해 봤다」고 쓰지 않습니다. 메모에 없다는 것과 해 본 적이 없다는 것은 다릅니다. 예: 메모에 구글 광고가 없을 때 「아직 운영해 보지 않은 구글 광고」라고 쓰지 않고, 「구글 광고에도 적용해 보겠습니다」처럼 계획으로만 쓴 뒤 경험이 있는지는 「확인 필요」에 올립니다.
   - 메모가 따로 적은 두 사실을 잇지 않습니다. 예: 메모에 알림톡 시나리오와 쿠폰 A/B 테스트가 따로 적혀 있으면 「알림톡에 넣을 쿠폰」이라고 쓰지 않습니다.
   - 메모의 동사를 역할이나 한 일이 달라지는 동사로 바꾸지 않습니다. 예: 「같이 함」을 「같이 맞췄습니다」로, 「참여함」을 「주도했습니다」로 바꾸지 않습니다.
   - 원 스킬 예시에 나오는 「강의로 배우는 중」 같은 준비 · 학습 문장과, 강의 · 자격증 · 봉사처럼 새 직무로 이어지는 경험도 메모에 있을 때만 씁니다.
2. **결과가 먼저 나오게, 구체적으로 씁니다.** 문단과 주요 성과의 첫머리에 결과나 결론을 두고, 「담당 업무 나열」 대신 내가 한 행동을 씁니다. 숫자는 경험 정리표 값을 그대로 씁니다.
3. **문항이 확인하려는 것부터 정합니다.** 자기소개서 문항마다 「이 문항으로 회사가 확인하려는 것」을 한 줄로 먼저 쓰고(예: 지원동기 → 왜 이 회사 · 이 직무인지, 직무역량 → 일을 해낸 근거, 성장과정 → 일하는 방식이 생긴 배경, 장단점 → 자기 객관화, 입사 후 포부 → 직무를 이해한 구체적 계획), 그에 맞는 경험을 고릅니다. 한 경험을 여러 문항에 겹쳐 쓰지 않고, 겹칠 수밖에 없으면 점검표에 적습니다.
4. **AI 티 점검은 `korean-humanizer` 기준으로 합니다.** 뜻 · 사실 · 숫자 · 고유명사는 그대로 두고, 탐지한 흔적에만 손댑니다. 변경률이 30%를 넘으면 점검표에 경고를 적고, 50%를 넘으면 그 윤문을 되돌립니다. 지원서는 공적인 글이라, 그 설명서의 「PERSONALITY AND SOUL」(의견 · 여담 · 흐트러짐 넣기)은 자기소개서의 성장과정처럼 어울리는 곳에만 조금 쓰고, 이력서 · 경력기술서에는 쓰지 않습니다. 세는 법, 심각도가 엇갈릴 때의 처리, 지원서에서 세지 않는 것, 등급 보정은 5단계에 있습니다.
5. **개인정보는 밖으로 보내지 않습니다.** 이름 · 연락처 · 주소 · 생년월일은 이력서 머리에만 쓰고 다른 파일에 옮기지 않습니다. 맞춤법 검사(외부 사이트)에는 자기소개서 본문만 보내되, 숫자를 가린 사본(7단계)을 보내고, 사용자가 동의할 때만 보냅니다. 물을 수 없는 상황이면 맞춤법 검사는 하지 않고 점검표에 「사용자 동의 필요」로 남깁니다.
6. **합격 · 통과를 약속하지 않습니다.** 결과 안내에 「합격」 · 「AI 탐지기를 통과」 같은 말을 쓰지 않습니다.
7. **원 스킬의 홍보 · 참고 링크는 옮기지 않습니다.** 원 스킬이 추천하는 서비스 · 템플릿 판매 링크는 결과물에 넣지 않습니다.
8. **사용자의 언어로 씁니다.** 한국어 서류는 한국어로 쓰고, ResumeSkills의 영어 틀(Summary · Bullet 등)은 한국 서류 항목으로 바꿉니다. 영문 이력서가 필요하다고 하면 따로 만듭니다.
9. **서류의 문장 부호는 한국 지원서 관례를 따릅니다.** 가운뎃점은 앞뒤를 띄우지 않고 붙여 씁니다(예: 결제·송금). 이렇게 두세 낱말을 묶은 가운뎃점은 5단계에서 AI 흔적(J-2)으로 세지 않습니다. 인용 · 강조는 작은따옴표(' ')를 쓰고 낫표(「」)는 쓰지 않습니다. 줄표(— · –)는 쓰지 않습니다. 맞춤법 검사를 못 하는 경우에도 이 기준으로 봅니다.
10. **제출본에는 제출할 글만 둡니다.** 원 스킬의 분석 기록(고치기 전후의 성과, 숫자를 묻는 질문, 채용공고 맞춤 계획, 대안 문장)과 작성 메모는 `03-notes.md` · `04-notes.md`에 따로 두고, `03-resume.md` · `04-cover-letter.md`에 붙이지 않습니다. 사용자가 실수로 메모까지 함께 내지 않게 하려는 것입니다.

## 한 번에 진행 (기본값)

사용자가 따로 말하지 않으면 아래 기본값으로 끝까지 진행합니다. 묻는 곳은 0단계의 한 번뿐입니다(최대 3개). 사용자가 「알아서」라고 하거나, 하위 에이전트 · 예약 실행처럼 물을 수 없으면 묻지 않고 `[확인 필요]`를 남기며 진행합니다.

| 정할 것 | 기본값 |
|---|---|
| 신입 · 이직 구분 | 경력이 1년 이상이면 이직, 아니면 신입. 애매하면 0단계에서 물음 |
| 서류 종류 | 신입: 이력서 + 자기소개서 문항. 이직: 이력서 + 경력기술서(+ 자기소개서 문항이 있으면 함께) |
| 자기소개서 문항 | 사용자가 준 문항과 글자 수. 없으면 지원동기 · 직무역량 · 성장과정 · 입사 후 포부 네 문항, 각 700자(공백 포함) |
| 글자 수 기준 | 공백 포함, 제한의 90~100%. 회사가 공백 제외라고 밝히면 그 기준 |
| 경력기술서 | 최근 경력부터, 회사마다 담당 업무 · 주요 프로젝트(자세히) · 주요 성과 3~5개(프로젝트 결과를 한 줄씩 요약) |
| 면접 질문 | 기본으로 만듭니다(서류에 쓴 경험은 면접에서 묻기 때문). 사용자가 「서류만」이라고 하면 건너뜁니다. 서류에 쓴 경험마다 질문 2개 + 꼬리 질문 1개, 답의 뼈대는 결론 → 상황 → 행동 → 결과 → 배운 점, 말하면 40~60초 |
| 맞춤법 검사 | 사용자가 동의할 때만 |

## 진행 순서

원 스킬은 원래 이름(예: `resume-bullet-writer`)으로 불러 쓰고, 입력 요약을 함께 넘깁니다. 스킬 도구로 부를 수 없거나 GPT 앱 · 하위 에이전트에서 돌릴 때는 `"$SK"/<이름>/SKILL.md`를 읽고 그 지시대로 합니다. 원 스킬의 분석 순서는 따르고, 이 파일은 입력 · 한국 서류 형식 · 사실 규칙 · 저장 위치만 정합니다.

k-skill 설명서(`instruction.md` · `SKILL.md`) 안에 있는 `npx … read` · `npx … exec` 명령은 실행하지 않습니다. 같은 내용은 `"$SK/dplanner-resume/vendor/k-skill/<이름>/"` 아래 파일에서 읽고, 실행은 이 파일의 명령으로 합니다.

작업 폴더 아래 `jobdocs/YYYYMMDD-<영문 짧은 이름>/`(날짜는 작업한 날)을 만들고 단계 결과를 차례로 저장합니다. 작업 폴더 이름이 이미 `jobdocs`이면 그 아래에 바로 만듭니다. 이 단계에서 만드는 임시 파일(`q1.txt` · 윤문 전 사본 등)도 모두 이 결과 폴더 안에 둡니다. 여러 작업이 같은 이름의 임시 파일을 덮어쓰지 않게 하려는 것입니다.

### 0단계: 입력 정리

- 받은 것을 `00-input.md`에 정리합니다: 지원 회사 · 직무 · 공고 원문(또는 공고 주소에서 읽은 내용), 내 이력(파일이면 파일 이름), 경험 메모, 자기소개서 문항과 글자 수 제한, 신입/이직.
- 메모 · 이력에 있는 이름 · 연락처 · 주소 · 생년월일은 `00-input.md`에 옮기지 않고 「지원자」로 적습니다(지킬 원칙 5). 이력서 머리에는 사용자가 준 원본에서 가져와 씁니다.
- 공고가 없으면 「직무 일반 요구」로 진행하고 `[가정]`을 붙입니다. 회사 정보를 웹에서 찾았으면 주소와 확인 날짜를 적습니다.
- 핵심이 빠졌고 사용자가 바로 답할 수 있으면 한 번만 묻습니다(최대 3개): 지원 공고, 숫자가 빈 경험, 문항 글자 수.

### 1단계: 경험 정리표

- `01-experience-cards.md`에 경험마다 한 칸씩 정리합니다: 이름 · 기간 · 상황(배경) · 문제 · 내가 한 행동(팀이 한 일과 나눠서) · 결과 · 이 경험이 보여 주는 역량 · 쓸 곳(서류 · 문항).
- 결과의 숫자마다 출처를 붙입니다: `[메모]` · `[이력서]` · `[사용자 답]` · `[확인 필요]`. 출처가 없는 숫자는 정리표에 넣지 않습니다. 메모 값으로 계산한 숫자(예: 18% → 26%는 8%p 상승)는 `[계산: 식]`을 붙이고, 6단계에서 식을 다시 확인합니다. 뒤 단계(7단계 글자 수 늘리기 등)에서 새 계산값(예: 3일·7일·12일에 보냄 → 모두 세 번)을 쓰려면, 먼저 이 표에 `[계산: 식]`으로 올린 뒤 씁니다.
- 행동이 「참여했다 · 도왔다」뿐이면, 내가 직접 한 부분이 무엇인지 0단계에서 묻거나 `[확인 필요]`를 남깁니다.

### 2단계: 공고 분석

- `job-description-analyzer`로 공고를 분석해 `02-posting-analysis.md`에 씁니다: 필요 역량 · 우대 사항 · 반복되는 키워드, 경험 정리표와 맞는 부분(경험 이름), 부족한 부분(내 경험으로 채울 수 없는 요구).
- 원 스킬의 「적합도 점수」는 참고로만 적고, 부족한 부분을 경험을 부풀려 메우지 않습니다.

### 3단계: 이력서 · 경력기술서

- `03-resume.md`에 씁니다. 한국 이력서 항목 순서: 인적사항 → 경력 요약(이직이면 2~3줄) → 학력 → 경력(회사 · 기간 · 직무) → 자격 · 어학 · 업무 도구 → 활동 · 수상. 이직이면 경력기술서를 같은 파일에 이어 씁니다: 회사마다 담당 업무 한 줄, 주요 프로젝트, 주요 성과 3~5개. 주요 프로젝트에는 프로젝트마다 기간 · 배경 · 한 일 · 결과를 자세히 쓰고, 주요 성과에는 그 회사에서 낸 결과를 한 일과 함께 한 줄씩 요약합니다. 두 칸의 역할이 달라서 같은 숫자가 두 곳에 나와도 됩니다.
- 경력기술서 문장 형식: 담당 업무 · 결과 · 주요 성과 줄은 개조식(명사로 끝맺음, 예: 「가입당 비용 약 31% 감소」)으로 쓰고, 배경 · 한 일처럼 설명하는 줄은 합쇼체 문장으로 씁니다. 한 줄 안에서 두 형식을 섞지 않습니다. 개조식 줄의 끝맺음 명사를 AI 흔적(A-6)으로 세지 않는 기준은 5단계 표에 있습니다.
- `resume-bullet-writer`로 주요 성과를 결과부터 쓰도록 고칩니다. `resume-quantifier`로 숫자를 넣을 자리를 찾되, 숫자는 경험 정리표에서만 가져옵니다(지킬 원칙 1). `resume-tailor`로 공고 키워드에 맞춰 순서와 표현을 고르되 사실은 바꾸지 않습니다. 직무나 산업이 바뀌는 이직(예: 커머스 → 핀테크)이면 `career-changer-translator`로 새 직무에 살릴 역량을 찾습니다. 이 스킬이 권하는, 경력을 회사 · 기간 순이 아니라 역량별로 묶는 이력서 형식은 쓰지 않고 위 한국 이력서 순서를 지킵니다. 강의 · 자격증 · 봉사 같은 경험과 「배우는 중」 문장도 메모에 있을 때만 씁니다(지킬 원칙 1).
- 원 스킬의 분석 기록은 `03-notes.md`에 둡니다(지킬 원칙 10).

### 4단계: 자기소개서

- `04-cover-letter.md`에 문항마다: 「이 문항이 확인하려는 것」 한 줄 → 고른 경험 → 본문. `cover-letter-generator`의 구조(도입 · 근거 · 회사와의 연결)는 영어 커버레터 틀이라, 한국 문항형(문항 하나에 답 하나, 글자 수 제한)으로 바꿔 씁니다.
- 본문은 첫 문장에 답(결론)을 두고, 상황 → 행동 → 결과 → 지원 회사 · 직무와의 연결 순서로 씁니다. 회사 정보는 0단계에서 확인한 사실만 씁니다.
- 「이 문항이 확인하려는 것」 · 고른 경험 · 원 스킬의 대안 문장은 `04-notes.md`에 두고, `04-cover-letter.md`에는 문항 제목과 본문만 둡니다(지킬 원칙 10).

### 5단계: AI 티 점검 · 윤문

- `vendor/k-skill/korean-humanizer/instruction.md`와 `references/ai-tell-taxonomy.md`를 읽고, 이력서 · 경력기술서 · 자기소개서마다 「탐지 → 윤문 → 감사 → 등급」을 돕니다.
- 윤문하기 전에 사본을 결과 폴더의 `drafts/<파일 이름>.draft.md`로 보관합니다. 이력서 사본에는 인적사항 표를 빼고 보관합니다(지킬 원칙 5). 인적사항은 윤문하지 않으므로 되돌릴 때도 필요하지 않습니다.
- 세는 법: 흔적은 글 속 한 자리(구절 하나)마다 1개로 셉니다. 정의에 「반복」이 들어간 패턴(예: C-10 · J-1)은 반복 묶음 하나를 1개로 셉니다. 두 파일(instruction.md · ai-tell-taxonomy.md)의 심각도가 다르면 더 높은 쪽을, 적용 조건(횟수)이 다르면 더 엄격한 쪽을 따릅니다(예: D-4는 분류표의 「3회 이상」이 아니라 설명서대로 1회만 나와도 S1). 한 파일에만 있는 표현(예: 「~와 함께」는 설명서의 A-1 · A-2 · A-3 예시에만 있음)도 그 파일의 심각도로 셉니다. 어느 쪽을 따랐는지 점검표에 적습니다.
- 지원서에서 세는 법(디플래너): 분류표의 문턱을 지원서에 그대로 쓰면, 합쇼체 · 개조식 · 가운뎃점 묶음처럼 한국 지원서의 관례까지 흔적으로 잡힙니다. 아래 표의 「세지 않는 것」은 흔적으로 세지 않고, 표에 없는 패턴은 위 세는 법대로 셉니다. 이 표는 위의 「더 엄격한 쪽」 규칙보다 먼저 적용합니다.

| 패턴 | 지원서에서 세지 않는 것 | 그래도 세는 것 |
|---|---|---|
| A-18 명사 앞 긴 관형절 | 관형절(꾸밈을 받는 명사는 빼고 셈)이 7어절 이하인 것. 예: 「주 2회 소재를 3개씩 올리는 방식」(5어절) | 8어절 이상인 것. 예: 「주 2회 소재를 3개씩 올리고 1주 단위로 성과가 좋은 소재만 남기는 테스트 방식」(11어절). 분류표 · 설명서의 A-18 예시도 9어절 관형절입니다 |
| A-6 명사화 | 경력기술서 개조식 줄의 끝맺음 명사(감소 · 도입 · 설계 등) | 뜻 없이 덧붙은 「진행 · 실시 · 수행 · 도모」. 예: 「협업 캠페인 진행」은 「협업 캠페인」으로 |
| J-2 가운뎃점 | 원칙 9에 따라 두세 낱말을 묶은 것. 예: 기획·실행, 3일·7일·12일 | 서술어를 잇거나(예: 빠르고·정확하고) 네 낱말 이상을 줄줄이 이은 것, 줄표 |
| J-1 · J-3 · C-10 서식 | 이력서 · 경력기술서의 표, 개조식 목록, 항목 머리말(담당 업무 · 결과 · 배경 · 한 일), 프로젝트 제목의 굵은 글씨, 회사가 준 문항 제목 | 문장 속 낱말을 굵게 칠한 강조, 자기소개서 본문에 넣은 목록 · 머리말 |
| E-2 같은 종결어미 | 합쇼체 「~습니다」로 끝나는 문장이 이어지는 것(지원서는 합쇼체로 통일하는 것이 관례) | 「~고 있습니다」를 기계적으로 붙인 진행형. 예: 「중요하게 생각하고 있습니다」는 「중요하게 생각합니다」로 |
| D-7 「X에서 Y로」 | 수치 변화. 예: 18%에서 26%로 | 수치가 아닌 「X에서 Y로」를 되풀이하는 것 |

- 변경률은 윤문 전 사본과 윤문 뒤 글의 본문(헤딩 · 표 · 구분선 · 빈 줄을 뺀 줄)으로 계산합니다. 표 · 헤딩이 많은 이력서를 파일 전체로 재면 변경률이 낮게 나오기 때문입니다. 아래 명령이 두 파일에서 본문만 뽑아 계산합니다(자기소개서는 파일 이름만 바꿈): `python -X utf8 -c "import sys,difflib; f=lambda p: chr(10).join(s for s in (l.strip() for l in open(p,encoding='utf-8')) if s and not s.startswith(('#','|','---'))); print(round((1-difflib.SequenceMatcher(None,f(sys.argv[1]),f(sys.argv[2])).ratio())*100,1),'%')" drafts/03-resume.draft.md 03-resume.md`
- 5단계를 끝낼 때(6단계에서 글을 고치기 전) 이 명령으로 「5단계 변경률」을 재서 적어 둡니다.
- 등급 보정(디플래너): 등급은 끝 단계에서 문서마다 한 번 매깁니다. S1 · S2 잔존과 자가검증은 제출본으로 보고, 변경률(등급 A의 조건과 자가검증 2번)은 「5단계 변경률」만 봅니다. 5단계를 끝낸 뒤(6단계 사실 확인, 7단계 글자 수 맞추기, 끝 단계의 재점검) 바뀐 양은 등급에 넣지 않고, 윤문 전 사본과 제출본을 비교한 「최종 변경률」로 따로 적습니다. 또 `korean-humanizer` 등급 A의 변경률 조건(10~25%)은 25% 이하만 보고 하한(10%)은 보지 않습니다. 쉼표 · 조사처럼 짧게 고치는 흔적만 있었거나 처음부터 흔적이 적은 문서는 흔적을 모두 고쳐도 변경률이 10%에 못 미쳐서, 하한을 보면 고친 양이 적다는 이유만으로 A를 받지 못하기 때문입니다.
- `06-check.md`의 「AI 흔적」 표에 문서마다 S1 · S2 · S3 개수(전 → 후), 변경률(5단계 · 최종), 등급(A~D), 대표 전후 문장 2~3개를 적습니다.
- 자기소개서에서 자주 보이는 상투적인 맺음(입사 후 포부를 막연한 다짐으로 끝내기, 깨달음을 일반론으로 정리하기)도 `korean-humanizer`의 마무리 상투구 기준으로 함께 봅니다.

### 6단계: 사실 확인

- 서류의 모든 문장에서 숫자 · 회사 · 기간 · 성과 · 자격을 뽑아, 경험 정리표와 0단계 입력에 있는지 대조합니다. 행동 · 대상 · 역할(누가 무엇을 어디까지 했는지)도 메모와 같은 범위인지 봅니다(지킬 원칙 1). 숫자를 맞춰 보는 것으로는 이런 차이가 드러나지 않으므로, 근거 칸에 메모 원문 구절을 짧게 옮겨 적고 서류 문장과 나란히 놓고 봅니다. `06-check.md`의 「사실 확인」 표: 문장 | 근거(경험 이름 · 출처 · 메모 원문 구절) | 판정(일치 · 불일치 · 확인 필요).
- 불일치는 경험 정리표 값과 메모 표현으로 고치고, 근거가 없는 문장은 지우거나 `[확인 필요]`로 바꿉니다. 고친 뒤 5단계 윤문으로 숫자가 바뀌지 않았는지 다시 봅니다.

### 7단계: 글자 수 · 맞춤법

- 글자 수는 추정하지 않고 실제로 셉니다. 문항 본문을 결과 폴더 안에 파일(`q1.txt`처럼, 문단 사이는 빈 줄 하나)로 저장한 뒤:
  - Node가 있으면: `node "$SK/dplanner-resume/vendor/k-skill/korean-character-count/scripts/korean_character_count.js" --file q1.txt --profile default --format text`
  - 없으면: `python -X utf8 -c "import sys; t=open(sys.argv[1], encoding='utf-8').read(); p=[x.strip() for x in t.splitlines() if x.strip()]; print('공백 포함(줄바꿈 제외)', sum(map(len,p)), '/ 공백 포함(문단 사이 줄바꿈 1자)', len(chr(10).join(p)), '/ 공백 제외', len(''.join(t.split())))" q1.txt`(한글 · 영문 · 숫자 · 문장부호만 있는 글에서는 두 방법의 값이 같습니다. 이모지가 있으면 Node 방법을 씁니다.)
  - 지원 사이트마다 줄바꿈을 세는 방식이 달라서, 줄바꿈을 뺀 값과 줄바꿈을 센 값을 함께 적고 둘 다 제한 안에 들게 맞춥니다.
- 제한을 넘거나 90%에 못 미치면 `korean-humanizer`의 「Length control」대로 늘리거나 줄이고 다시 셉니다. 늘릴 때는 경험 정리표에 있는 사실만 풀어 씁니다. 메모 값으로 새 계산값을 만들어 쓰려면 먼저 경험 정리표에 `[계산: 식]`으로 올립니다(1단계).
- 경험 정리표의 사실만으로 90%를 채울 수 없으면 억지로 늘리지 않습니다. 미달인 채로 두고, 「확인 필요」 목록에 늘릴 재료를 묻는 질문(그 일에서 맡은 부분 · 숫자 · 계기)을 올립니다. 늘리다가 변경률이 30%를 넘게 되어도 멈춥니다.
- 글자 수를 맞추려고 쓰거나 고친 문장은, 그 문장만 6단계 사실 확인과 5단계 흔적 점검을 다시 합니다.
- `06-check.md`의 「글자 수」 표: 문항 | 제한 | 공백 포함(줄바꿈 제외) | 공백 포함(줄바꿈 1자) | 공백 제외 | 판정(제한 초과 · 목표 미달 · 통과). 목표 미달은 제한 안에 들었지만 제한의 90%에 못 미친 것입니다.
- 맞춤법은 사용자가 동의했을 때만 합니다. 숫자를 가린 사본을 만들어 그 파일을 보냅니다(지킬 원칙 5):
  - `python -X utf8 -c "import sys,re; t=open(sys.argv[1],encoding='utf-8').read(); open(sys.argv[2],'w',encoding='utf-8').write(re.sub(r'[0-9]','0',t))" q1.txt q1.spell.txt`
  - `python -X utf8 "$SK/dplanner-resume/vendor/k-skill/korean-spell-check/scripts/korean_spell_check.py" --file q1.spell.txt --format text`
  - 결과에서 받아들인 고침과 받아들이지 않은 고침(고유명사 · 의도한 표현)을 나눠 적고, 받아들인 고침은 원본 `q1.txt`와 제출본에 옮깁니다.
- 마지막으로 제출본 두 파일에 줄표가 남았는지 셉니다(파일마다 0이어야 함): `python -X utf8 -c "import sys; [print(p, sum(open(p,encoding='utf-8').read().count(c) for c in (chr(8212), chr(8211)))) for p in sys.argv[1:]]" 03-resume.md 04-cover-letter.md`

### 8단계: 면접 예상 질문

- `interview-prep-generator`로 `05-interview.md`를 씁니다: 서류에 쓴 경험마다 질문 2개 + 꼬리 질문 1개, 답의 뼈대(결론 → 상황 → 행동 → 결과 → 배운 점). 답의 숫자 · 사실도 경험 정리표에서만 가져옵니다. 배운 점처럼 메모에 없는 본인의 생각은 지어내지 않고 `[본인이 채움: 무엇을]`으로 둡니다.
- 2단계에서 찾은 부족한 부분에서 나올 질문과 솔직하게 답하는 방법도 하나씩 적습니다.

### 끝: 점검표와 마지막 답변

- `06-check.md`를 마무리합니다: AI 흔적 · 사실 확인 · 글자 수 · 맞춤법(했으면) · 「확인 필요」 목록. 뒤 단계에서 고친 글은 앞 단계 수치를 바꾸므로, 표마다 「단계 값」과 「최종 값」을 나눠 적고 최종 값은 이 단계에서 제출본으로 다시 셉니다. AI 흔적 등급은 이 단계에서 문서마다 한 번 매깁니다(5단계의 등급 보정).
- 제출본을 다시 세다가 5단계에서 놓친 흔적을 찾으면 그 흔적을 고치고, 고친 글로 최종 값을 셉니다. 이것은 5단계 감사를 한 번 더 하는 것으로 보고, 찾은 흔적에만 손댑니다. 고친 문장은 6단계 사실 확인과 5단계 흔적 점검을 다시 하고, 고친 곳 수를 점검표에 적습니다.
- 제출할 파일은 `03-resume.md` · `04-cover-letter.md`입니다. `drafts/` 폴더와 `q*.txt`는 점검에 쓴 임시 파일이라 제출하지 않고, 점검이 끝나면 지워도 됩니다.
- 마지막 답변은 짧게: 만든 파일 위치(제출할 파일과 지워도 되는 임시 파일을 나눠서), 문서마다 AI 흔적 S1 개수(전 → 후)와 등급, 글자 수 표, 사용자가 확인할 것.
- GPT 앱이나 클로드 앱의 일반 채팅처럼 파일을 쓸 수 없는 곳에서는 같은 내용을 답변으로 보여 줍니다.
