# 한글 업무 스킬셋

디플래너가 만든 스킬입니다(문의 dplanner@outlook.kr). 아래 오픈소스를 씁니다.

- kordoc https://github.com/chrisryugj/kordoc (MIT): 한글 문서 읽기 · 양식 채우기 · 마크다운으로 공문서 만들기
- rhwp https://github.com/edwardkim/rhwp (MIT): 한글 문서 보기 · 쪽 그림(SVG · PNG) 내보내기
- k-skill https://github.com/NomaDamas/k-skill (MIT): 한국 업무 · 생활 스킬 모음

이 스킬을 받은 클로드 코드는 아래 순서를 지킵니다.

- 명령은 클로드 코드가 직접 실행합니다. 사용자에게 명령을 복사해 실행해 달라고 하지 않습니다.
- 설치 · 내려받기는 무엇을 어디서 받는지와 크기를 한 줄로 알리고 허락을 받은 뒤에 합니다. 처음 실행할 때 받는 크기: rhwp 약 31MB, kordoc 약 470MB(npm 캐시, 그중 문자 인식 엔진 onnxruntime-node가 약 290MB), k-skill 약 4MB.
- 만드는 것은 이 스킬 파일(`~/.claude/skills/hangul-work/`), 작업 폴더 `~/hangul-work/`, 위 npm 캐시뿐입니다. Node.js · Python이 없을 때만 허락을 받고 설치합니다.
- `~/hangul-work`는 사용자 홈 폴더 안의 `hangul-work` 폴더입니다. 명령에는 전체 경로를 씁니다(윈도우 예: `C:\Users\<사용자>\hangul-work\문서\보고서.hwpx`).
- 만든 문서는 초안입니다. 제출 · 발송 · 결재 요청처럼 바깥으로 나가는 일은 하지 않고, 파일을 만들어 위치를 알려 주는 데서 멈춥니다.
- 단계가 끝날 때마다 한 줄로 보고합니다. 실패하면 오류 줄을 보여 주고, 원인을 고친 뒤 다시 합니다.

## 1. 이 스킬 설치

사용자가 이 파일을 주며 「이 스킬 설치해줘」라고 하면 먼저 이 절을 합니다.

1. `~/.claude/skills/hangul-work/SKILL.md`가 이미 있으면 알리고, 덮어써도 되는지 묻습니다.
2. 이 파일 전체를 요약하거나 고치지 말고 그대로 `~/.claude/skills/hangul-work/SKILL.md`에 저장합니다.
3. 저장한 파일의 첫 줄이 `---`이고 `name: hangul-work`가 있는지 확인합니다.
4. 이어서 2절부터 진행해도 되는지 묻습니다. 사용자가 「세팅까지 해줘」라고 했으면 묻지 않고 진행합니다.

## 2. 준비 확인

1. 운영체제(윈도우 · 맥)를 확인합니다.
2. `node -v`(20 이상)와 파이썬(`python --version` 또는 `python3 --version`, 3.10 이상)을 확인합니다. 버전 숫자가 나오지 않으면 없는 것으로 봅니다(윈도우에서는 `python`을 치면 스토어가 열리기도 합니다). 없으면 무엇이 없는지 알리고, 허락을 받으면 설치합니다.
   - 윈도우: `winget install --id OpenJS.NodeJS.LTS -e` · `winget install --id Python.Python.3.13 -e`
   - 맥: `brew install node python` (Homebrew가 없으면 https://nodejs.org · https://www.python.org 의 설치 파일)
   - 설치한 뒤에는 새 터미널에서 다시 확인합니다. k-skill은 윈도우에서 `python`을 부르고, 다른 이름이면 환경 변수 `KSKILL_PYTHON`으로 실행 파일을 알려 줄 수 있습니다.
3. 작업 폴더를 만듭니다.
   ```text
   ~/hangul-work/
   ├─ 문서/   다 만든 한글 파일
   ├─ 작업/   보고서 원고(.md) · 값 파일(.json) · 조회 결과(.json)
   ├─ 확인/   쪽 그림(SVG · PNG)
   ├─ 양식/   사용자가 준 서식 파일
   └─ tools/  rhwp
   ```

## 3. 도구 준비

1. kordoc: `npx -y kordoc@4 fill --list-templates`를 실행합니다. 기안문 서식 목록(JSON)이 나오면 준비된 것입니다. 처음에는 내려받느라 시간이 걸립니다.
2. k-skill은 명령 이름과 성공 여부를 사용량 통계로 보냅니다. 사용자에게 한 번 알리고 기본으로 끕니다. 클로드 코드는 명령마다 셸을 새로 열므로, **k-skill 명령 줄마다** 환경 변수를 같은 줄에 붙입니다.
   - PowerShell: `$env:KSKILL_ANALYTICS_DISABLED='1'; npx -y @nomadamas/k-skill@0 version`
   - bash · zsh: `KSKILL_ANALYTICS_DISABLED=1 npx -y @nomadamas/k-skill@0 version`
   - 버전(예: 0.11.2)이 나오면 준비된 것입니다. 아래 k-skill 명령에도 모두 같은 앞부분을 붙입니다.
3. rhwp(문서 보기용): 최신 릴리스 https://github.com/edwardkim/rhwp/releases/latest 에서 운영체제에 맞는 파일과 같은 릴리스의 `SHA256SUMS.txt`를 `~/hangul-work/tools/rhwp-dl/`에 받습니다.
   - 윈도우 `rhwp-v*-windows-x86_64.zip`, 맥 `rhwp-v*-macos-aarch64.tar.gz`(애플 실리콘) · `rhwp-v*-macos-x86_64.tar.gz`(인텔)
   - 해시 확인: 윈도우 `(Get-FileHash <파일> -Algorithm SHA256).Hash`, 맥 `shasum -a 256 <파일>`. 값이 `SHA256SUMS.txt`의 그 파일 줄과 같아야 합니다(대소문자는 무시).
   - 풀기: 윈도우 `Expand-Archive <zip> ~/hangul-work/tools/rhwp`, 맥 `tar -xzf <파일> -C ~/hangul-work/tools/rhwp`
   - 윈도우판은 압축 안에 `rhwp` 폴더가 한 겹 더 있어서 실행 파일이 `tools/rhwp/rhwp/rhwp.exe`입니다. 맥판은 폴더 안에서 `rhwp` 실행 파일을 찾아 씁니다.
   - 그 실행 파일로 `--version`을 확인합니다(예: `rhwp v0.9.0`). rhwp가 막혀도 문서 만들기(kordoc)는 되므로, 알리고 다음으로 넘어갑니다.

## 4. 업무 레시피

### 4-1. 정부지원 신청서 · 양식 빈칸 채우기

1. 사용자가 준 양식 파일(HWP · HWPX)과 회사 정보(회사 소개서 · 사업자등록증 내용 · 메모 등)를 받습니다. 원본 양식은 `양식/`에 복사해 두고 덮어쓰지 않습니다.
2. 양식을 먼저 읽고, 채울 칸을 봅니다.
   ```bash
   npx -y kordoc@4 <작업 폴더>/양식/<양식 파일> -o <작업 폴더>/작업/<양식 이름>.md
   npx -y kordoc@4 fill <작업 폴더>/양식/<양식 파일> --dry-run
   ```
   - 읽은 마크다운과 원본 쪽 그림(5절 1번)에서 단위 칸(원 · USD · 명)과 표 밖 본문의 자리 표시(ㅇㅇㅇ · ○○○)를 찾아 둡니다. dry-run에는 단위 칸이 나오지 않습니다.
   - dry-run 결과의 `fields`에서 `value`가 비어 있는 칸의 `label`이 채울 칸입니다. 「기업 기본 정보」 같은 제목 줄도 섞여 나오므로 빼고 봅니다. `value`에 이미 글이 있는 라벨(예: 「서약인」의 값 「기 업 명:」)도 채울 칸이 아닙니다.
   - 같은 라벨이 여러 곳(예: 신청서와 서약서의 「기업명」)에 있으면 같은 값이 모두 들어갑니다. 곳마다 다른 값이 필요하면 사용자에게 알립니다.
3. 값 파일(JSON)을 `작업/`에 씁니다. 키는 `label`을 쓰고(띄어쓰기는 달라도 kordoc이 맞춰 줍니다), 값은 회사 정보에 적힌 그대로 씁니다.
   - 회사 정보에 없는 칸은 비워 두고, 끝난 뒤 빈 칸 목록을 알려 줍니다. 숫자 · 날짜 · 번호는 지어내지 않습니다.
   - 단위 칸(원 · USD · 명)이 따로 있으면 값에는 숫자만 씁니다.
   - 법인등록번호 칸이 있으면 회사 정보의 법인등록번호를 넣습니다. 모양(6-7자리)은 주민등록번호와 같지만 법인 정보입니다.
4. 미리 보기로 값마다 들어갈 칸(표 · 행 · 열)을 봅니다. 결과의 `unmatched`가 빈 목록이면 모든 키가 칸을 찾은 것입니다. 엉뚱한 칸에 들어가는 값이 있으면 키를 고칩니다.
   ```bash
   npx -y kordoc@4 fill <작업 폴더>/양식/<양식 파일> -j <작업 폴더>/작업/<값>.json --dry-run
   ```
5. 채워서 저장합니다. HWP 양식도 서식을 그대로 둔 채 HWPX로 저장됩니다.
   ```bash
   npx -y kordoc@4 fill <작업 폴더>/양식/<양식 파일> -j <작업 폴더>/작업/<값>.json -o <작업 폴더>/문서/<이름>.hwpx
   ```
6. 5절로 확인합니다. 아래는 표 칸 채우기로 들어가지 않으므로, 끝난 뒤 목록으로 알립니다.
   - 날짜 · 서명 · 날인 칸: 사용자에게 남깁니다. 양식에 미리 찍힌 날짜 · 연도가 오늘과 맞지 않으면(예: 11월에 받은 「2026. 5.」 양식) 공고 기간이 남았는지 확인하라고 알립니다.
   - 표 밖 본문의 자리 표시(ㅇㅇㅇ 등): 한글에서 직접 고치라고 알립니다.
   - 사업 내용처럼 긴 글을 쓰는 칸: 사용자가 원할 때만 초안을 `작업/`에 .md로 써서 보여 줍니다. 회사 정보에 재료(제품 특성 · 경쟁력 · 추진 계획 등)가 없으면 쓰지 않고, 회사 소개서나 사업 계획 자료를 달라고 합니다.
7. 만든 신청서는 초안입니다. 제출 · 업로드는 하지 않고, 제출 전에 회사 정보 원본과 대조하라고 알립니다.

### 4-2. 메모 → 한글 보고서 · 회의록

1. 사용자가 준 메모(회의 메모 · 업무 메모 · 표로 옮길 내용)와 원하는 문서 종류를 확인합니다. 종류를 말하지 않으면 「보고서」로 만들고, 회의록 · 계획서 · 개조식 · 보도자료 서식도 있다고 한 줄로 알립니다. 회의 메모면 회의록 서식(`--preset 회의록`)도 있다고 알립니다.
2. 작성 부서와 작성일을 받습니다. 말하지 않으면 메모에 나온 부서와 오늘 날짜를 쓴다고 알립니다. 결재란을 원하면 직위(예: 담당 · 팀장 · 본부장)를 받습니다.
3. 원고(마크다운)를 `작업/`에 씁니다.
   - 메모에 없는 내용(숫자 · 날짜 · 사람 · 결정)은 지어내지 않습니다. 메모가 모호하면 묻거나 「확인 필요」로 적습니다.
   - 순서: `# 제목` → `> (목적)하고자 함` 한 줄(요약 상자가 됨) → `1. 회의 개요`처럼 번호로 쓴 장 제목(□) → 그 아래 두 칸 들여 쓴 `- ` 항목(ㅇ). 결정 사항 · 할 일은 표(항목 · 내용 · 담당 · 기한)로 씁니다. 표는 장 제목 아래에 빈 줄을 하나 두고, 들여 쓰지 않습니다.
   - 요약 상자 한 줄에는 점이 든 날짜(예: 「11. 12.」)를 쓰지 않습니다. kordoc이 그 점을 문장 끝으로 세어 문체 경고를 냅니다.
   - 원고 예:
     ```markdown
     # 마케팅팀 주간회의 결과 보고

     > 연말 프로모션 일정과 광고 예산 방향을 정하고자 함

     1. 회의 개요
       - 참석: 마케팅팀 4명, 디자인팀 1명

     2. 결정 사항

     | 항목 | 내용 | 담당 | 기한 |
     | --- | --- | --- | --- |
     | 연말 프로모션 | 12월 1일부터 24일까지 진행 | 확인 필요 | - |
     ```
4. 한글 파일로 만듭니다.
   ```bash
   npx -y kordoc@4 generate <작업 폴더>/작업/<원고>.md -o <작업 폴더>/문서/<이름>.hwpx --preset 보고서 --no-cover --report-info "(YYYY. M. D., <작성 부서>)" --approval "담당,팀장,본부장"
   ```
   - 한 쪽짜리 보고서는 `--no-cover`로 표지를 끕니다. 표지를 끄면 `--org` · `--date`(표지에만 쓰임)는 문서에 들어가지 않으므로, 작성일 · 부서는 `--report-info`로 제목 아래 한 줄에 넣습니다.
   - 결재란이 필요 없으면 `--approval`을 빼고, 직위는 사용자가 말한 대로 쉼표로 이어 씁니다.
   - 문체 경고가 나와도 종료 코드가 0이면 파일은 만들어진 것입니다.
5. 5절로 확인하고 파일 위치를 알려 줍니다.

### 4-3. 결재 올릴 간이기안문(내부 보고서 표지와 결재란)

1. 받을 값: 제목 · 요약 한 줄 · 결재 직위(최대 4칸, 예: 담당 · 과장 · 팀장 · 본부장) · 협조 부서 · 작성 기관 · 생산등록번호 · 날짜 · 공개 구분. 날짜는 등록일 · 결재일 · 작성일 세 칸에 들어가므로, 따로 말하지 않으면 같은 날짜를 넣는다고 알립니다. 빈 칸은 한글에서 누름틀 안내 글이 그대로 보이므로, 모르는 값은 물어봅니다.
2. 값 파일(JSON)을 `작업/`에 씁니다. 칸 이름: 생산등록번호 · 등록일 · 결재일 · 공개구분 · 결재직위1 · 결재직위2 · 결재직위3 · 결재직위4 · 협조자 · 제목 · 요약설명 · 작성일 · 작성기관
3. 먼저 미리 보기로 값이 모두 칸에 맞는지 봅니다. 결과의 `unmatched`가 빈 목록이면 모든 값이 칸에 들어간 것입니다.
   ```bash
   npx -y kordoc@4 fill --template gian-simple -j <값>.json --dry-run
   npx -y kordoc@4 fill --template gian-simple -j <값>.json -o <작업 폴더>/문서/<이름>.hwpx
   ```
4. 본문이 필요하면 4-2처럼 `--preset 보고서`로 본문 문서를 따로 만듭니다.
- 대외 시행문은 일반기안문(`--template gian`, 23칸)입니다. 칸 목록은 `npx -y kordoc@4 fill --list-templates`로 봅니다.

### 4-4. 거래처 실사 → 한글 보고서

1. 사업자등록번호(10자리)와 상호를 받습니다. 동네 사업장이면 시군구와 업종도 받습니다.
2. 실사를 하고 결과를 파일로 저장합니다(결과가 50KB 안팎이라 화면 출력으로는 잘립니다).
   ```powershell
   $env:KSKILL_ANALYTICS_DISABLED='1'; npx -y @nomadamas/k-skill@0 exec biz-health-check scripts/biz_health_check.py -- <사업자번호> --name "<상호>" | Out-File -Encoding utf8 <작업 폴더>/작업/<상호>-실사.json
   # 동네 사업장: --name 뒤에 --region <시군구> --industry <업종>
   # bash · zsh: KSKILL_ANALYTICS_DISABLED=1 npx -y ... > <작업 폴더>/작업/<상호>-실사.json
   ```
   - 저장한 JSON의 `sections` 항목마다 `status`를 봅니다.
   - `unavailable`이면 이유를 `sections.<항목>.note` 또는 `sections.<항목>.data.note`에서 찾아, 보고서에 「직접 확인 필요」와 함께 적습니다. 조회 실패를 「문제없음」으로 쓰지 않습니다.
   - `ok`여도 국민연금처럼 후보가 여러 곳이고 `selected_candidate`가 `null`이면, 가입자 수 등은 「직접 확인 필요」로 적습니다.
   - 조회 시각은 각 항목의 `looked_up_at`을 씁니다. 운영 서버 캐시에서 온 결과(`cache.hit: true`)는 `proxy.requested_at`이 원래 조회 시각입니다.
   - 체납 명단 결과는 이름으로만 대조한 것이라(명단에 사업자번호가 없음) 보고서에 그렇게 적습니다.
   - 국세청 사업자 상태 · 국민연금 · 금융위 법인 정보 · 부정당제재는 k-skill 운영 서버(k-skill-proxy.nomadamas.org)를 거칩니다. 조회한 사업자번호와 상호가 그 서버로 간다는 것을 사용자에게 한 번 알립니다.
   - 윈도우에서 체납 명단만 `CERTIFICATE_VERIFY_FAILED`로 실패하면, 파이썬이 쓰는 윈도우 인증서 저장소에 국세청 누리집의 루트 인증서가 아직 없는 경우입니다. 사용자에게 알리고, 허락을 받으면 `curl.exe -sI https://www.nts.go.kr/`를 한 번 실행한 뒤 다시 실사합니다(윈도우가 신뢰하는 루트 인증서를 자동으로 받아 오면 다음 조회가 됩니다). 원하지 않으면 `note`에 적힌 주소에서 직접 확인하라고 안내합니다. 인증서 검증을 끄지는 않습니다.
3. 보고서 원고(마크다운)를 `작업/`에 씁니다.
   - 순서: `# 제목` → `> (목적)하고자 함` 한 줄(요약 상자가 됨) → 확인 대상 → 확인 결과(항목 · 결과 · 출처 표) → 검토 의견
   - 장 제목은 `## 확인 대상`처럼 쓰면 Ⅰ · Ⅱ · Ⅲ 띠 제목이 되고 그 아래 `- ` 항목은 □가 됩니다. `1. 확인 대상`처럼 번호로 쓰면 장 제목이 □가 되고, 그 아래는 두 칸 들여 쓴 `- ` 항목(ㅇ)으로 씁니다.
   - 점수 · 등급 · 위험 판정은 쓰지 않고, 조회한 사실과 출처 · 조회 시각만 씁니다. 표 칸 글은 짧게 씁니다.
4. 한글 파일로 만듭니다.
   ```bash
   npx -y kordoc@4 generate <작업 폴더>/작업/<원고>.md -o <작업 폴더>/문서/<이름>.hwpx --preset 보고서 --org "<회사 · 기관명>" --date "YYYY. M. D."
   ```
   - 표지가 있는 서식이라 `--date`를 꼭 넣습니다. 빼면 kordoc 4.24.64는 표지 날짜를 「2026. 11..」처럼 점을 두 번 찍습니다.
   - 「보고서」 서식은 표지(빈 문서정보표 · 제목 · 날짜 · 기관명)를 자동으로 넣습니다.
   - 문체 · 줄 꺾임 경고가 나와도 종료 코드가 0이면 파일은 만들어진 것입니다. PowerShell에서는 이 경고가 오류처럼 보이므로 종료 코드로 판단합니다.
   - 다른 서식: `--preset` 에 계획서 · 개조식 · 회의록 등(목록은 kordoc 설명서 https://github.com/chrisryugj/kordoc).
5. 5절로 확인하고 파일 위치를 알려 줍니다.

### 4-5. 나라장터 발주계획 찾기 → 한글 표

1. 분야(물품 `goods` · 공사 `construction` · 용역 `service` · 외자 `foreign`), 검색어, 발주 시기를 받습니다.
2. 찾고 결과를 파일로 저장합니다.
   ```powershell
   $env:KSKILL_ANALYTICS_DISABLED='1'; npx -y @nomadamas/k-skill@0 exec g2b-order-plan-search scripts/g2b_order_plan.py -- --kind service --keyword <검색어> --order-from YYYY-MM --order-to YYYY-MM --limit 20 | Out-File -Encoding utf8 <작업 폴더>/작업/발주계획.json
   ```
3. 결과의 `items`로 표를 만듭니다: 발주기관(`orderInsttNm`) · 사업명(`bizNm`) · 발주 시기(`orderYear`년 `orderMnth`월) · 합계 금액(`sumOrderAmt`) · 계약 방법(`cntrctMthdNm`) · 게시일(`nticeDt`) · 상세 주소(`orderPlanDtlUrl`). 담당 공무원 이름 · 전화번호는 사용자가 원할 때만 넣습니다. 전체 건수는 `total_count`입니다.
4. 4-4의 3 · 4처럼 원고를 쓰고 한글 파일로 만듭니다.

### 4-6. 받은 한글 파일 읽기 · 요약

- 읽기: `npx -y kordoc@4 <파일> -o <작업 폴더>/작업/<파일>.md`로 마크다운을 만들어 읽고 요약합니다(HWP · HWPX · PDF · 오피스 문서).
- 빈칸이 있는 양식이면 4-1로 채웁니다. 원본 서식 파일은 덮어쓰지 않습니다.

### 4-7. 그 밖의 한국 업무 스킬(k-skill)

1. `npx -y @nomadamas/k-skill@0 list`로 스킬 목록을 봅니다(명령 앞에 3절 2번의 환경 변수를 붙입니다).
2. 쓸 스킬의 사용법은 `npx -y @nomadamas/k-skill@0 instruct <스킬 이름>`으로 받아 그대로 따릅니다. 예: 법령 검색과 신 · 구조문대비표(`korean-law-search`), 전자공시(`k-dart`), 정부지원사업 공고(`government-support-survey`).
3. 그 스킬이 API 키나 로그인을 요구하면 알리고 멈춥니다. 결제 · 제출 · 발송은 하지 않습니다.

## 5. 결과 확인

1. 클로드가 확인할 때: `<rhwp 실행 파일> export-png <파일>.hwpx --vlm-target claude -o <작업 폴더>/확인/<이름>`을 실행합니다. `<이름>`은 폴더이고, 그 안에 쪽마다 PNG가 생깁니다. 표 칸 글자가 작아 읽기 어려우면 `--vlm-target` 없이 `--scale 2 -p <쪽 번호(0부터)>`로 그 쪽만 한 번 더 그립니다. `--vlm-target claude`와 `--scale 2`를 함께 쓰면 그림 크기 한도를 넘어 실패합니다. 값을 글자로 대조하려면 `npx -y kordoc@4 <파일>.hwpx -o <작업 폴더>/작업/<이름>.md`로 다시 읽습니다.
2. 사용자에게 보여 줄 때: `<rhwp 실행 파일> export-svg <파일>.hwpx -o <작업 폴더>/확인/<이름>`으로 만든 SVG를 브라우저로 열게 안내합니다. 한컴오피스가 있으면 한글 파일을 그대로 열면 되고, 없으면 rhwp 웹 데모(https://edwardkim.github.io/rhwp/)나 rhwp 크롬 · 엣지 확장으로 엽니다.
3. 확인할 것: 값이 맞는 칸에 들어갔는지, 작성일 · 작성 부서 · 결재란이 들어갔는지, 서식이 자동으로 넣는 글(표지 날짜 · 쪽 번호 등)이 맞는지 봅니다. 이상하면 사용자에게 알립니다. rhwp가 「웹폰트를 준비하지 못한 글꼴」을 알리면 대체 글꼴로 그린 그림이라, 줄 꺾임은 한글에서 다시 보라고 알립니다.

## 6. 지킬 것

- 회사 · 기관 문서를 클로드에 넣어도 되는지는 그 조직의 보안 규정을 따릅니다. 공공기관 내부망 문서는 넣지 않습니다.
- 주민등록번호 · 계좌번호 같은 개인 정보는 원고에 넣지 않습니다.
- 만든 문서는 초안입니다. 제출하기 전에 원문 · 원자료와 대조하라고 알립니다.
