# 2D 모션그래픽 쇼츠 만들기 (디플래너 방식, 2026-11-05 판)

디플래너 채널이 실제 쇼츠를 만들 때 쓰는 순서와 규칙을 그대로 옮겼습니다. 사용자가 할 일은 주제를 정하고, 나온 영상을 보고 말로 피드백하는 것입니다. 나머지는 이 순서대로 진행하고, 단계마다 결과를 보여 준 뒤 다음으로 넘어갑니다.

## 0. 준비 (처음 한 번)

1. 필요한 프로그램: Node.js 18 이상, ffmpeg. 없으면 사용자에게 무엇을 왜 설치하는지 말하고 동의를 받은 뒤 공식 방법으로 설치합니다.
2. 영상 프로젝트: `npx create-video@latest`로 Remotion 빈 프로젝트를 만듭니다(1080×1920, 30fps 컴포지션 하나).
   - Remotion 라이선스: 개인, 직원 3명 이하 영리 조직, 비영리 단체는 무료입니다. 그 밖의 회사는 회사 라이선스가 필요합니다(https://www.remotion.dev/license). 사용자에게 한 번 알려 줍니다.
3. 목소리: 사용자가 쓰는 AI 음성 도구(또는 직접 녹음)로 문장마다 파일 하나씩 만듭니다. API 키는 사용자가 직접 넣게 하고, 대화 · 파일 · 코드에 적지 않습니다.
4. 캐릭터 영상(선택): 분할 화면 아래에 깔 6초 안팎 세로 영상 2~3개. AI 영상 도구로 「마이크 앞에서 차분하게 설명하며 고개를 끄덕이고 손짓하는 사람, 카메라 고정」처럼 만듭니다. 없으면 단색 배경에 큰 아이콘으로 대신합니다.

## 1. 대본

- 8문장 안팎, 소리 내어 읽어 25초 안팎.
- 구조: 후킹(첫 문장) → 사용법 → 세팅 → CTA(댓글 → DM).
- 첫 문장에는 「이걸 쓰면 뭐가 편해지는지」를 담습니다. 톤은 「적당히 맛있게」입니다. 슴슴하지도, 광고처럼 세지도 않게, 친구가 「이거 봐 봐」 하고 보여 주듯 씁니다.
- 쉬운 말로 씁니다. 중학생이 한 번에 알아듣게 쓰고, 전문 용어는 쉬운 말로 바꿉니다.
- 사실이 아닌 내용(없는 기능, 확인되지 않은 숫자)은 쓰지 않습니다. 숫자에는 출처를 남깁니다.
- 댓글 키워드는 2자 이내로 정합니다(예: 「쇼츠」 · 「그림」). 길면 댓글이 줄어든다는 경험칙이 있습니다.
- 출력은 표로 받습니다: 번호 | 읽는 문장 | 자막 조각(한 줄 15자 안쪽, 읽는 말과 같은 글자) | 강조할 낱말.
- 문장을 쓸 때 화면도 같이 정합니다. 문장 2~3개가 화면 하나를 함께 설명하도록 묶습니다(3절).

## 2. 목소리 다듬기 (ffmpeg)

문장 파일마다 앞뒤 무음을 자르고, 1.265배 빠르게 하고, 높이를 반음 0.5 낮추고(목소리가 들떠 들릴 때), 음량을 맞춥니다. 높이를 바꾸지 않으려면 `asetrate` 두 단계를 빼고 `atempo=1.265`만 씁니다.

```bash
ffmpeg -y -i line01.mp3 -af "silenceremove=start_periods=1:start_threshold=-45dB:start_silence=0.02,areverse,silenceremove=start_periods=1:start_threshold=-45dB:start_silence=0.06,areverse,aresample=48000,asetrate=46634,aresample=48000,atempo=1.30207,loudnorm=I=-16:TP=-2:LRA=11" -ar 48000 -ac 2 line01.wav
```

- 반음 0.5 낮춤: 48000 × 2^(−0.5/12) ≈ 46634, atempo = 1.265 ÷ 0.97153 ≈ 1.30207.
- 문장 사이 쉼은 0.04초, 후킹 뒤 쉼은 0.25초입니다. 문장 시작 시점(프레임)을 계산해 영상 코드에 넘깁니다.

## 3. 화면 설계 (가장 중요)

| 규칙 | 내용 |
|---|---|
| 크기 | 1080 × 1920, 30fps, 어두운 바탕 |
| 화면 묶음 | 화면을 4~6개로 묶습니다. **한 화면은 3초 이상** 유지합니다. 문장마다 화면을 바꾸면 정신없습니다 |
| 분할 | 위에 PIP 화면 카드(1020 × 900을 0.86배, 위 96px), 아래에 캐릭터 영상(440px 내려 모자~가슴이 보이게) |
| 확대 | 카드를 원래 크기(왼쪽 30, 위 270)로 키우고 캐릭터는 숨깁니다. 분할 → 확대 → 분할 순서로 흐름을 만들고, 바뀔 때 12프레임에 걸쳐 부드럽게 바꿉니다 |
| 화면 내용 | 그린 모형보다 **실제 결과 화면**(캡처 · 녹화)을 씁니다. 캡처는 3배 해상도로 찍고 2~3배 확대해 흐름을 따라 카메라를 옮깁니다. 글자가 세로 영상 기준 40px 안팎으로 보여야 합니다 |
| 아이콘 | 글자만 두지 말고 **큰 아이콘**(지름 120~200px, 선 아이콘)과 함께 둡니다 |
| 자막 | 한 줄, 66px, 굵게, 강조 낱말만 형광연두(#CCFF00), 짙은 그림자. **세로 1300px 아래로 내려가지 않게** 둡니다(릴스 아래쪽은 캡션 · 버튼이 덮음) |
| 전환 | 앞 화면 위로 다음 화면이 나타나게 합니다(카드가 비는 순간이 없게) |
| 소리 | 클릭 · 휙 · 띵 효과음은 작게, 배경음은 아주 작게, 둘 다 영상에 직접 넣습니다 |

핵심 코드(Remotion, 그대로 가져다 씁니다):

```jsx
import {interpolate, Easing} from 'remotion';
const ease = {extrapolateLeft: 'clamp', extrapolateRight: 'clamp', easing: Easing.inOut(Easing.cubic)};

// 분할(0) ↔ 확대(1): pts = [[프레임, 0 또는 1], ...]. 바뀌는 지점 앞뒤 6프레임에 걸쳐 바꾼다.
export const layoutAt = (pts, f) => {
  let L = pts[0][1];
  for (let i = 1; i < pts.length; i++) {
    const [c, v] = pts[i];
    if (f < c - 6) break;
    L = interpolate(f, [c - 6, c + 6], [L, v], ease);
  }
  return L;
};
// 카드 위치: s = 0.86 → 1, top = 96 → 270, left = (1080 - 1020 * s) / 2, transform: scale(s), transformOrigin: '0 0'
// 캐릭터 투명도: interpolate(L, [0, 0.7], [1, 0]). 자막 top: 분할 1190, 확대 1200.

// 카메라: keys = [[프레임, {z, cx, cy}], ...]. cx, cy는 캡처 이미지에서 화면 가운데에 둘 점(캡처 CSS 좌표).
export const camAt = (f, keys) => {
  if (f <= keys[0][0]) return keys[0][1];
  for (let i = 1; i < keys.length; i++) {
    const [fa, a] = keys[i - 1];
    const [fb, b] = keys[i];
    if (f <= fb) {
      const k = interpolate(f, [fa, fb], [0, 1], ease);
      return {z: a.z + (b.z - a.z) * k, cx: a.cx + (b.cx - a.cx) * k, cy: a.cy + (b.cy - a.cy) * k};
    }
  }
  return keys[keys.length - 1][1];
};
// 이미지 배율 S = max(카드폭 / 캡처폭, 카드높이 / 캡처높이) * z. 이미지 왼쪽 = 카드폭/2 - cx*S, 위 = 60 + 카드높이/2 - cy*S.
// 확대해도 캡처 바깥이 보이지 않게 cx, cy를 [카드폭/2/S, 캡처폭 - 카드폭/2/S] 안으로 제한한다.
```

## 4. 영상으로 뽑기

```bash
npx remotion render src/index.ts Shorts out/raw.mp4 --codec=h264 --crf=18
ffmpeg -y -i out/raw.mp4 -c:v copy -af loudnorm=I=-14:TP=-1.5:LRA=11 -c:a aac -b:a 192k out/final.mp4
```

- 컴퓨터가 느리면 GitHub Actions에서 같은 명령을 돌립니다(우분투 러너에 ffmpeg · 한글 글꼴 `fonts-noto-cjk` 설치). 디플래너 기준 25초 영상 하나가 5분 안팎입니다.

## 5. 확인 (영상을 보여 주기 전에 반드시)

1. 장면 11장을 뽑습니다: `ffmpeg -ss <길이×i/12> -i out/final.mp4 -frames:v 1 still-i.jpg`.
2. 확인할 것: 자막이 1300px 위에 있는지, 화면마다 3초 이상인지, 카드가 비는 순간이 없는지, 확대 장면 글자가 읽히는지, 실제 화면 속 낱말(키워드 등)이 대본과 같은지.
3. 문제가 있으면 고쳐서 다시 뽑고, 사용자에게는 영상과 장면 모음을 함께 보여 줍니다.
