# fable-escalate: 평소엔 Opus, 막히면 Fable

평소에는 Opus 5.5로 빠르고 싸게 일하고, 막히는 지점에서만 Fable 5.2를 불러 맡깁니다.

- Fable 5.2는 어려운 추론과 오래 걸리는 에이전트 작업에 강합니다.
- 대신 토큰 가격이 Opus 5.5의 두 배(100만 토큰당 입력 $8 · 출력 $40)이고, 쉬운 요청에도 늘 생각하므로 반복 작업에 쓰면 느리고 비쌉니다.
- 앤트로픽도 대부분의 작업은 Opus로 시작하고, Opus로 부족할 때 Fable 5.2로 바꾸라고 안내합니다.

## 1. 설치

사용자가 이 파일을 주며 「이 스킬 설치해줘」라고 하면 아래를 차례로 합니다.

1. `~/.claude/skills/fable-escalate/SKILL.md`와 `~/.claude/agents/fable-solver.md`가 이미 있는지 먼저 확인합니다. 하나라도 있으면 무엇이 있는지 알려 주고, 덮어써도 되는지 물은 뒤 허락을 받으면 진행합니다.
2. 이 파일 전체를 요약하거나 고치지 말고 그대로 `~/.claude/skills/fable-escalate/SKILL.md`에 저장합니다.
3. 아래 「3. 하위 에이전트 정의」의 코드 블록 안쪽 내용만 그대로 `~/.claude/agents/fable-solver.md`에 저장합니다(코드 블록 표시 줄은 빼고, 첫 줄이 `---`가 되게).
4. 두 파일을 다시 읽어 첫 줄이 `---`이고 `name`이 각각 `fable-escalate` · `fable-solver`인지 확인합니다.
5. 사용자에게 알립니다.
   - 새 세션을 열어야 적용됩니다.
   - 메인 모델은 Opus 5.5로 두세요(`/model`에서 고름).
   - Fable 5.2는 막힐 때만 불리고, 부르기 전에 한 줄로 알려 드립니다.

## 2. 언제 Fable 5.2를 부르나

다음 가운데 하나라도 해당하면 `fable-solver`에게 맡깁니다.

- 같은 오류나 같은 테스트 실패를 두 번 고쳤는데 세 번째에도 같은 원인으로 실패합니다.
- 원인을 모르는 버그가 여러 파일이나 모듈에 걸쳐 있고, 어디부터 볼지 정하지 못합니다.
- 깊은 추론이 필요한 과제입니다: 알고리즘 · 수학 · 동시성 · 성능 병목 설계, 큰 구조를 바꾸는 결정.
- 사용자가 「깊게 생각해서」, 「어려운 문제」, 「심화」처럼 어려운 일이라고 밝힙니다.

다음 경우에는 부르지 않고 지금 모델이 직접 합니다.

- 파일 이동 · 이름 바꾸기 · 서식 맞추기 · 같은 수정을 여러 곳에 되풀이하기 · 문서 정리 같은 반복 작업
- 한두 번 만에 고칠 수 있는 단순한 버그
- 보안 공격 기법이나 연구용 생물학 작업(Fable 5.2가 대부분 막습니다)

## 3. 하위 에이전트 정의

설치할 때 아래 코드 블록 안쪽을 `~/.claude/agents/fable-solver.md`로 저장합니다.

````markdown
---
name: fable-solver
description: Claude Fable 5.2로 도는 어려운 문제 해결사. 메인 에이전트가 막혔을 때만 쓴다. 같은 오류가 두 번 고친 뒤에도 되풀이될 때, 원인을 모르는 버그가 여러 파일에 걸쳐 있을 때, 알고리즘 · 수학 · 큰 구조처럼 깊은 추론이 필요할 때 쓴다. 반복 작업이나 단순 수정에는 쓰지 않는다.
model: claude-fable-5-2
---

당신은 메인 에이전트가 막혀서 불려 온 선임 엔지니어입니다.

1. 브리프의 목표 · 완료 조건 · 이미 시도한 것을 먼저 읽고, 같은 시도를 되풀이하지 않습니다.
2. 관련 파일을 직접 읽고 오류를 재현해 근본 원인을 찾습니다. 추측으로 고치지 않습니다.
3. 가장 작은 변경으로 고치고, 완료 조건(테스트 등)을 직접 실행해 확인합니다.
4. 끝나면 짧게 보고합니다: 근본 원인, 바꾼 파일과 내용, 확인한 결과, 남은 위험.
5. 브리프가 하지 말라고 한 것은 하지 않습니다. 범위를 넘는 변경이 필요하면 직접 하지 말고 제안만 합니다.
````

## 4. 맡기는 방법

1. 맡기기 전에 사용자에게 한 줄로 알립니다. 예: 「같은 오류가 세 번째라서 여기서부터 Fable 5.2에 맡길게요.」
2. Agent 도구로 `fable-solver`를 부르고, 브리프에 다음을 넣습니다.
   - 목표와 완료 조건(예: 어떤 테스트가 통과해야 하는지)
   - 관련 파일 경로
   - 지금까지 시도한 것과 각 시도의 오류 원문
   - 건드리면 안 되는 것
3. 한 작업에서 Fable 5.2는 두 번까지만 부릅니다. 두 번에도 풀리지 않으면 사용자에게 상황을 보고하고 다음 방법을 묻습니다.
4. 결과를 받으면 지금 모델이 직접 확인합니다(테스트 실행 · 오류 재현). 확인한 뒤에 적용하고, Fable 5.2가 무엇을 했는지 한 줄로 알립니다.

## 5. 모델 ID가 듣지 않을 때

- `fable-solver.md`의 `model`은 별칭 `fable`로 바꾸지 말고 전체 모델 ID `claude-fable-5-2` 그대로 둡니다. 별칭은 클로드 코드 · 앱 버전에 따라 이전 Fable(예: 5.1)로 연결될 수 있습니다.
- `fable-solver`를 부를 때 모델을 찾을 수 없다는 오류가 나면 클로드 코드를 최신 버전으로 업데이트하고 새 세션을 엽니다.
- 쓰는 요금제에서 Fable을 쓸 수 없으면 `fable-solver`를 부르지 말고 지금 모델의 effort를 높여(`/effort`) 다시 시도합니다.
