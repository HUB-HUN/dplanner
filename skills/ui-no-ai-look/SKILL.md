# AI 티 안 나는 UI 스킬

만든 곳: 디플래너(@dplanner_official) · 문의 dplanner@outlook.kr
근거: Anthropic 블로그 「Improving frontend design through Skills」(2025-11-12)의 원칙을 디플래너가 한국어 화면에 맞게 새로 정리했습니다.

## 0. 코드를 쓰기 전에 먼저 정한다
- 이 화면이 누구를 위한 무엇인지, 사용자가 이 화면에서 끝내야 할 일을 한 줄로 적는다.
- 분위기를 세 단어로 정한다. 「깔끔한」 · 「모던한」처럼 흔한 단어는 쓰지 않는다.
- 아래 1~4를 정해서 먼저 보여 주고, 그다음에 코드를 쓴다.

## 1. 글꼴
- Inter · Roboto · Arial · 시스템 기본 글꼴을 쓰지 않는다. 제목 글꼴과 본문 글꼴을 따로 정하고 웹폰트 주소까지 적는다.
- 한글 화면이면 한글 웹폰트(예: Pretendard, 페이퍼로지)를 따로 지정한다.
- 제목은 아주 굵게(800~900), 본문은 가늘게(300~400) 둔다. 제목 크기는 본문의 3배 이상으로 한다.

## 2. 색
- 색은 4~6개만 정하고 CSS 변수(--color-bg, --color-text, --color-primary, --color-accent, --color-muted)로 정의한다.
- 주색 하나를 넓은 면적에 쓰고, 강조색은 한 화면에서 한두 곳에만 쓴다.
- 흰 바탕의 보라색 그라데이션은 쓰지 않는다. 여러 색을 비슷한 비중으로 나누지 않는다.

## 3. 움직임
- 페이지가 처음 열릴 때 요소가 순서대로 나타나는 움직임을 한 번만 잘 설계한다.
- 모든 섹션에 같은 페이드인을 붙이지 않는다. 마우스를 올렸을 때의 반응은 버튼과 카드에만 짧게 둔다.

## 4. 배경과 배치
- 단색 대신 옅은 격자 · 점 무늬 · 겹친 그라데이션 · 잡음 질감 가운데 하나로 깊이를 준다.
- 똑같은 둥근 카드를 줄지어 놓지 않는다. 크기와 간격에 차이를 둔다.

## 5. 다 만든 뒤 점검한다
- [ ] 글꼴이 기본 글꼴이 아니다.
- [ ] 보라색 그라데이션이 없다.
- [ ] 똑같은 카드가 줄지어 있지 않다.
- [ ] 페이드인이 모든 섹션에 붙어 있지 않다.
- [ ] 한 화면에서 눈에 띄는 곳이 한 곳이다.

하나라도 걸리면 그 항목만 고치고 나머지는 그대로 둔다.
